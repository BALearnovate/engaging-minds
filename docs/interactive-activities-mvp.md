# Interactive Activities Platform MVP — Architecture & Implementation Plan

## 1. Executive Summary
This document outlines the architecture and implementation strategy for the AI-Powered Interactive Learning Activity Platform MVP. The core directive is that **AI generates structured Activity Definitions (DSL)**—never executable HTML, JS, or React code. The frontend renders activities using a **Component Registry**, while student interactions emit events for real-time teacher classroom monitoring and intervention.

## 4. Activity Definition DSL (`ActivityDefinition`)

Activity definitions conform strictly to schema version `"1.0"`.

### Core DSL Schema Types
- `ActivityDefinition`: Top-level container.
  - `schemaVersion`: `"1.0"`
  - `title`: `string`
  - `description`: `string` (optional)
  - `estimatedDurationMinutes`: `number` (optional)
  - `blocks`: `ActivityBlock[]`

- `ActivityBlock`:
  - `id`: `string`
  - `type`: `ActivityBlockType`
  - `title`: `string` (optional)
  - `instructions`: `string` (optional)
  - `config`: `MultipleChoiceConfig | FillBlankConfig | FlashcardsConfig | TrueFalseConfig | OrderingConfig | DragDropConfig | FindHotspotsConfig | ClockDiagramConfig`

- `ActivityBlockType`:
  1. `"multiple_choice"`
  2. `"fill_blank"`
  3. `"flashcards"`
  4. `"true_false"`
  5. `"ordering"`
  6. `"drag_drop"`
  7. `"find_hotspots"`
  8. `"clock_diagram"`

## 5. 3-Tier Validation Pipeline (`backend/src/activities/validation/`)

Every activity definition generated by AI or submitted by a teacher passes through a 3-tier validation architecture before execution:

1. **Tier 1: Zod Schema Validation (`zodSchemas.ts`)**
   - Validates JSON structure, required types, array counts, and block config schemas.
2. **Tier 2: Deterministic Structural & Referential Integrity (`activityValidator.ts`)**
   - Verifies unique block IDs.
   - Ensures multiple choice `correctAnswer` matches one of the provided options.
   - Ensures fill-in-the-blank passage placeholders (`[1]`, `[2]`) match blank IDs.
   - Verifies ordering `correctOrder` contains all item IDs without missing/duplicate entries.
   - Verifies drag & drop `correctItemIds` in target bins reference existing `draggableItems`.
   - Verifies find hotspots target `x` and `y` percentage coordinates fall within `0..100`.
   - Verifies clock diagram hour slots fall in valid range (1–24) without duplicate hour slots.
3. **Tier 3: Semantic Quality Validation (`activityValidator.ts`)**
   - Ensures non-empty educational content, age appropriateness, title/description clarity, and student instructions.

## 6. Component Registry Architecture (`frontend/src/registry/`)

The Component Registry decouples activity rendering, validation, event reduction, and teacher editing:

```typescript
export interface ActivityComponentDefinition<TConfig = unknown, TResponse = unknown> {
  type: ActivityBlockType;
  label: string;
  description: string;
  validate(config: unknown): ValidationResult;
  renderStudent(props: StudentBlockProps<TConfig, TResponse>): React.ReactNode;
  renderTeacherEditor(props: TeacherEditorProps<TConfig>): React.ReactNode;
  calculateProgress(state: StudentBlockState, config: TConfig): BlockProgress;
  reduceEvent(state: StudentBlockState, event: ActivityEvent): StudentBlockState;
}
```

Registered Block Types:
1. `multiple_choice`: Radio/card options with single correct answer key.
2. `fill_blank`: Passage text with `[1]`, `[2]` blank tokens and answer key array.
3. `flashcards`: Flip card deck with prompt & answer sides.
4. `true_false`: Statement card with True/False toggles and optional explanation.
5. `ordering`: Re-orderable item list with expected sequence verification.
6. `drag_drop`: Draggable items matching designated drop target bins.
7. `find_hotspots`: Interactive diagram canvas where learners discover designated target spots.
8. `clock_diagram`: Interactive circular analog clock face diagram where learners assign activities to each hour slot.

## 7. Database & Versioning Strategy

### Entities
- `Activity`: Core entity owned by a teacher.
- `ActivityVersion`: Immutable snapshot of a published or draft activity.
  - Version `1`, `2`, `3`...
  - `status`: `'DRAFT' | 'PUBLISHED'`
  - `definition`: JSON (`ActivityDefinition`)
- `ActivitySession`: Live classroom session tied to an immutable `ActivityVersion`.
  - `shareCode`: Unique 6-character code (e.g. `ABC-742`).
- `StudentSession`: Student instance in a live classroom session.
  - `status`: `'NOT_STARTED' | 'IN_PROGRESS' | 'STUCK' | 'COMPLETED'`
  - `progress`: `0..100` percentage
  - `score`: total score achieved
- `ActivityEvent`: Audit log of student interactions and teacher interventions.

### Immutability Constraint
Editing a draft activity produces a new `ActivityVersion`. Ongoing student sessions reference `ActivityVersion.id` and are **never** mutated by subsequent teacher edits.

## 8. AI Generation & Google Gemini API Engine

- `AiActivityGeneratorService`:
  - Connects to Google Gemini API (`gemini-2.5-flash`) using `GEMINI_API_KEY`.
  - System prompt enforces structured JSON output (`responseMimeType: "application/json"`), DSL schema `1.0`, unique block IDs, age-appropriate secondary school content, and no executable code.
  - Auto-sanitizes and normalizes block metadata before running the 3-Tier Validator.
  - Fallback deterministic generator available if API key is omitted or unreachable.
  - `generate(prompt: string, subject?: string, gradeLevel?: string): Promise<ActivityDefinition>`
  - `improveBlock(block: ActivityBlock, prompt: string): Promise<ActivityBlock>`
